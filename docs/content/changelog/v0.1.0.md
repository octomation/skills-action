# v0.1.0 — Ship the skill with the tool.

The first release. A tool's release workflow publishes its agent skill to the
[octolab/skills](https://github.com/octolab/skills) catalog, and the catalog's
CI checks itself with the same code.

## Publish from a tool

```yaml
- name: Publish the agent skill
  uses: octomation/skills-action@v0.1.0
  with:
    tool: <tool>
    token: ${{ steps.catalog.outputs.token }}
```

- Copies `skills/<tool>/` from the released commit into `plugins/<tool>/`,
  with `plugin.json`, `provenance.json` and a regenerated `marketplace.json`,
  in one commit signed by the token's GitHub App, and tags it `<tool>--vX.Y.Z`.
- Accepts only an annotated, signed and verified release tag with a published,
  non-prerelease GitHub release, from the tool's registered repository.
- A published release is frozen; downgrades are refused. Running it again is
  safe: it recovers a missing catalog tag and retries when another tool
  publishes at the same time.
- Outputs `changed`, `catalog-commit`, `catalog-tag` and `payload-digest`.

## Check the catalog

`command: check` fails on stale generated files, an invalid registry, payload,
digest or `<tool>--v*` tag, or a `claude plugin validate` finding; `discovery`
compares a skills CLI run with the published plugins.

## For catalog maintainers

```bash
npx --yes github:octomation/skills-action#v0.1.0 generate
npx --yes github:octomation/skills-action#v0.1.0 check
```

## Compared with `octolab/skills/.github/actions/publish`

The publisher moved here from the catalog. Inputs `dry-run` and
`allow-unverified-tag` are gone; `source-token` is now `github-token`, the
workflow's own token by default, so callers pass nothing.
