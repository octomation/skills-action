# v0.2.1 — The published record of a tool.

Nothing changes for the workflows that call `publish` or `check`: their
inputs, outputs and what they accept are those of v0.2.0. The new command
`inspect` lets the catalog's workflows read what a catalog checkout publishes
for a tool without parsing `provenance.json` themselves.

## Inspect

- `command: inspect` with `tool` reads `plugins/<tool>/` of the checkout at
  `path`, at any commit or tag of the catalog. It does not read `catalog.json`
  and needs no token, network, git or `claude`.
- It reads both forms of `provenance.json`, with `skills` and without, and
  gives the outputs `version`, `source-repository`, `source-tag`,
  `source-commit`, `skills-paths` and `skills-digests`: the last two are JSON
  objects of every published skill, the main skill first.
- It fails, naming the problem, if the record has a schema other than 1 or
  another tool, a malformed source, a skill name or path that a publisher
  never writes, or lacks the main skill or lists it other than first; if the
  plugin's skill folders are not the skills of the record; or if a folder no
  longer hashes to its recorded digest.
- `octolab-skills inspect <tool>` prints the same as JSON in a catalog
  checkout.

## Publish

- A replay reads the skills of its own `provenance.json` with the rule
  `inspect` uses; what it accepts and refuses is that of v0.2.0.
