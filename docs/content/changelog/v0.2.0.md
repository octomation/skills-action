# v0.2.0 — Extra skills of a tool.

A tool can publish extra skills next to its main one, and agents see them as
`<tool>:<name>`. Workflows of tools with one skill need no change: their
inputs, their `catalog.json` entries and their files in the catalog stay as
they are.

Roll it out in this order: the catalog's CI moves to v0.2.0 first, then the
catalog registers `extra-skills`, then the tool releases with both skills
through the action at v0.2.0. `check` v0.1.1 accepts the `extra-skills` key
but refuses a plugin that holds the folder of an extra skill, and a publisher
before v0.2.0 ignores the key and publishes the main skill only, which
`check` v0.2.0 accepts.

## Publish

- A tool registers extra skills in the catalog's `catalog.json` under the new
  optional key `extra-skills`, a list of names. Each lives in the sibling
  folder of the main skill, `skills/<name>/`, with `name` equal to the folder,
  `metadata.tool` the tool and `metadata.version` equal to the release tag.
- A new publication reads every registered skill at the release tag and fails
  if one is missing there; a folder that is not registered is not published.
- A re-run of a published release compares with that release's
  `provenance.json`, not with the current registry, and writes nothing.
- `provenance.json` keeps `version`, `source` and `digest` of the main skill
  and, for a tool with extra skills, adds `skills`: every published skill with
  its path and digest. A tool with one skill writes it as before.
- The new output `skills-digests` is a JSON object of every published skill
  and its digest. `payload-digest` stays the digest of the main skill.

## Check

- `check` requires a plugin's skill folders to be the skills its
  `provenance.json` lists, each registered for the tool; a registered skill
  that a published version lacks is valid.
- `discovery` expects every published skill of every plugin.
- `check` refuses an extra skill named like another tool or another tool's
  extra skill, since agents install skills by name: a catalog that v0.1.1
  accepted can be refused.
